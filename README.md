# Мусорка — MVP 0.1.6

Локальная Windows-утилита для разбора рабочего хвоста: Рабочий стол + Загрузки, массовые решения по файлам и папкам, реестр «Потом», перенос в Google Drive, реестр и штатное удаление установленных программ, журнал действий.

## Что уже есть

- скан Рабочего стола и Загрузок, включая подпапки;
- таблицы «Файлы» и «Папки» переразмечены: правые столбцы больше не должны сжиматься до нечитаемого состояния;
- для выбранного файла и папки полный путь всегда показывается отдельной строкой под таблицей без обрезания;
- добавлена кнопка «Копировать путь», а имя и путь в таблице получили всплывающую подсказку с полным путём;
- **выбор любой дополнительной локальной папки** через обычный диалог Windows; выбранные папки запоминаются между запусками и могут быть убраны из списка;
- **отдельный реестр папок**: полный путь, зона, число файлов внутри и рекурсивный размер;
- перенос выбранных файлов с Рабочего стола/из Загрузок в `C:\Загрузки` без перезаписи одноимённых файлов;
- массовые решения по вложенным папкам: **«Папку в корзину» / «Удалить папку навсегда»**;
- все корневые зоны сканирования, включая вручную выбранные папки, защищены от удаления;
- перед удалением папки приложение повторно считает её содержимое и останавливается, если оно изменилось после сканирования;
- если внутри папки есть файлы со статусом **«Оставить» / «Потом» / «В Google Drive»**, удаление папки блокируется до разбора конфликта;
- переход из вкладки «Папки» прямо к отфильтрованным файлам этой папки;
- категории: выгрузки/аналитика, документы, PDF, архивы, изображения, установщики, код/данные и т. д.;
- **точный фильтр по формату/расширению**: `.csv`, `.xlsx`, `.pdf`, `.zip` и т. д., включая файлы без расширения;
- массовое выделение файлов: **«Выделить все показанные»** / **«Снять выделение»**, счётчик выделения, Shift/Ctrl/Ctrl+A; кнопка «Выделить все показанные» работает по текущему набору после фильтрации;
- фильтр файлов по конкретной локальной папке;
- поиск одинаковых файлов: SHA-256 считается только для групп одинакового размера;
- массовые решения:
  - **Оставить**;
  - **В Google Drive**;
  - **В корзину**;
  - **Удалить навсегда**;
  - **Потом**;
- **«Потом» — отдельный реестр с полным путём**, размером, датой, заметкой и признаком «файл всё ещё существует»;
- единый **План уборки** перед разрушительными действиями;
- отдельное второе подтверждение, если в плане есть **«Удалить навсегда»**;
- Google Drive: OAuth через браузер, просмотр папок, создание папок, выбор папки назначения;
- для Drive: `upload -> проверка размера и MD5, если Google его отдаёт -> локальный файл в Корзину`;
- установленные программы из Windows Registry с ручными статусами **Перенести / Не нужно / Не знаю**;
- **«Удалить программу»** запускает штатный зарегистрированный Windows-деинсталлятор; файлы программы напрямую не стираются;
- для MSI-записей команда обслуживания `/I{product-code}` переводится в штатное удаление `/X{product-code}`;
- кнопка «Открыть папку установки»;
- экспорт программ со статусом «Перенести» в CSV;
- история выполненных действий.

## Безопасность удаления

Пометка файла ничего не удаляет. Реальное действие происходит только на вкладке **«План уборки»** после подтверждения.

- **В корзину** использует Корзину Windows.
- **Удалить навсегда** физически удаляет файл и требует дополнительного подтверждения со списком путей.
- Перед любым выполнением приложение повторно проверяет размер и время изменения файла. Если файл изменился после сканирования, действие останавливается fail-closed: нужно пересканировать и принять решение заново.
- **В Google Drive** сначала загружает файл и проверяет, что загрузка совпадает по размеру (и MD5, если доступен). Только после этого локальный файл перемещается в Корзину Windows.
- Вложенные папки можно удалить через тот же **План уборки**. Для папки показывается рекурсивный объём и число файлов; перед фактическим удалением они считаются повторно. Изменившаяся папка удаляться не будет.
- Корневые зоны сканирования (**Рабочий стол / Загрузки / вручную выбранные папки**) не могут быть поставлены на удаление.
- Папки с файлами, явно помеченными **«Оставить» / «Потом» / «В Google Drive»**, не ставятся на удаление, пока конфликт не разобран.
- **Удаление программ** не означает `rm -rf Program Files`: приложение запускает только зарегистрированный в Windows деинсталлятор. Завершение деинсталляции остаётся под контролем Windows/самой программы и может запросить UAC.

## Выбор любой папки

На вкладке **«Обзор»** есть блок **«Папки для сканирования»**:

1. нажмите **«Добавить папку…»**;
2. выберите любую доступную локальную папку или диск в системном диалоге Windows;
3. нажмите **«Сканировать выбранные папки»**.

Рабочий стол и Загрузки остаются включены по умолчанию. Дополнительные папки сохраняются в локальной базе настроек и автоматически участвуют в следующих сканированиях. Кнопка **«Убрать выбранную»** исключает дополнительную папку из будущих сканирований. Если выбранная папка уже находится внутри другой сканируемой зоны, приложение не обходит её второй раз.

## Быстрый запуск на рабочем Windows-компьютере

1. Распаковать папку `musorka_mvp`.
2. Запустить `install_and_run.bat`.
3. На первом запуске установятся зависимости в локальную `.venv` рядом с приложением.
4. Дальше можно запускать `Musorka.vbs` двойным щелчком — без окна командной строки. `run_musorka.bat` остаётся запасным запуском.

Нужен Python 3.11+ с Windows launcher `py`.

## Google Drive — подключение

Для просмотра уже существующих папок Drive и загрузки в произвольные папки нужен OAuth Desktop client.

### Один раз в Google Cloud

1. Создать или выбрать Google Cloud project.
2. Включить **Google Drive API**.
3. Открыть **Google Auth platform** и настроить приложение.
   - Для корпоративного Google Workspace можно использовать `Internal`, если это разрешено организацией.
   - Для обычного Gmail обычно нужен `External`; если приложение остаётся в режиме Testing, добавить свой Google-аккаунт в test users.
4. Открыть **Google Auth platform -> Clients**.
5. Нажать **Create Client**.
6. Выбрать **Application type -> Desktop app**.
7. Создать client и скачать JSON.

### В «Мусорке»

1. Открыть вкладку **Google Drive**.
2. Нажать **Выбрать OAuth client JSON** и указать скачанный файл.
3. Нажать **Подключить / проверить Drive**.
4. Откроется Chrome: выбрать нужный Google-аккаунт и подтвердить доступ.
5. После подключения нажать **Открыть выбор папки** — появится дерево папок Drive; можно заходить внутрь и создавать новые папки.

JSON клиента и OAuth-токен хранятся локально в `%APPDATA%\Musorka` и не входят в проект.

В самой вкладке Google Drive есть кнопки **«Открыть Google Cloud Console»** и **«Открыть официальную инструкцию Google Drive API»**.

## Где хранится состояние

`%APPDATA%\Musorka\musorka.sqlite3`

Там лежат только метаданные: пути, папки, решения, заметки, программа переноса и журнал. Сами файлы в базу не копируются.

Также в `%APPDATA%\Musorka` после подключения Drive находятся:

- `google-oauth-client.json`;
- `google-token.json`.

## Сборка EXE

На Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\build_exe.ps1
```

Результат появится в `dist\Musorka\Musorka.exe` (или в каталоге `dist\Musorka`, в зависимости от версии PyInstaller).

В текущей среде:

## Что не считаю проверенным здесь

Текущая среда не Windows. Поэтому до первого живого прогона нельзя утверждать, что уже проверены:

- чтение реального Windows Registry на рабочем компьютере;
- запуск реального зарегистрированного деинсталлятора и UAC;
- перенос папки в Корзину Windows через Send2Trash;
- окончательное удаление реальной рабочей папки;
- реальные пути Known Folders при корпоративных перенаправлениях/OneDrive;
- Корзина Windows;
- OAuth и загрузка в конкретный Google Drive;
- итоговая Windows-сборка PyInstaller.

Первый live-smoke должен пройти именно на рабочем Windows-компьютере.
